# Данные проекта

Данные каталога лежат в `public/js/data/` в виде обычных JS-файлов. Один и тот же файл работает в двух местах: в браузере (автономный режим, офлайн-кеш) и на сервере — при первом запуске им заполняется база SQLite (`server/db.js → seed`). Справочники — `public/js/shared/dict.js`.

| Файл | Что внутри |
|---|---|
| `routes.js` | 25 маршрутов: «паспорт», описания, этапы, доступность, правила, источники |
| `tracks.js` | треки и профили высот (генерируется, не редактировать вручную) |
| `restrictions.js` | база правил посещения: 14 правил с основаниями и ссылками |
| `gear.js` | 74 позиции снаряжения в 9 категориях с правилами подбора |
| `shared/dict.js` | федеральные округа, регионы, категории и статусы доступности, ландшафты, особенности |

## Маршрут

| Поле | Тип | Смысл |
|---|---|---|
| `slug` | строка | адрес страницы: `#/routes/<slug>` |
| `title`, `area`, `areaType` | строки | название, территория, тип: `np` — национальный парк, `zap` — заповедник, `pp` — природный парк, `pam` — памятник природы, `none` — вне ООПТ |
| `region` | код | субъект РФ из справочника (по нему определяется федеральный округ) |
| `difficulty` | 1–5 | очень лёгкий, лёгкий, средний, сложный, экспедиция |
| `lengthKm`, `gainM`, `durationH`, `topM` | числа | длина, набор высоты, время в пути, высшая точка |
| `days` | `[мин, макс]` | сколько дней занимает маршрут |
| `type` | `loop` / `radial` / `linear` | кольцевой, туда и обратно, из точки А в точку Б |
| `months` | `[1..12]` | рекомендуемый сезон |
| `landscapes`, `features` | коды | для фильтров: лес, горы, вода… / можно с детьми, с детской коляской, без машины… |
| `summary`, `description`, `highlights`, `stages` | тексты | описание и этапы (`[название, км от старта, что там]`) |
| `easy` | список фраз | **«Коротко и простыми словами»**: короткие предложения, по одной мысли |
| `tiflo` | текст | **тифлокомментарий**: что вокруг, под ногами и на что ориентироваться — для незрячих и слабовидящих |
| `env` | пары | условия на тропе: покрытие, уклоны, места отдыха, инфраструктура |
| `start` | объект | точка старта, координаты, как добраться (в том числе без машины) |
| `access` | `{K,O,S,G,U}` | паспорт доступности, см. ниже |
| `restrictions` | `[[код правила, пояснение]]` | какие правила посещения действуют на маршруте |
| `safety` | список | советы по безопасности именно для этого маршрута |
| `sources` | `[[название, ссылка]]` | первоисточники: официальные сайты ООПТ, документы |
| `check` | `{date, level}` | когда сверено и как: `official` — с официальным сайтом, `open` — по открытым источникам |

Каждый маршрут проверяется схемой `route` из `logic.js` — и при загрузке данных в тестах, и при сохранении через администрирование.

## Паспорт доступности

Категории и статусы взяты из методики паспортизации объектов (приказ Минтруда России от 25.12.2012 № 627), чтобы оценки были понятны и посетителям, и сотрудникам ООПТ, которые уже работают с паспортами доступности.

| Код | Категория посетителей | На сайте |
|---|---|---|
| К | передвигаются на креслах-колясках | «Передвигаюсь на коляске» |
| О | с нарушениями опорно-двигательного аппарата | «Мне трудно ходить» |
| С | с нарушениями зрения | «Не вижу или плохо вижу» |
| Г | с нарушениями слуха | «Не слышу или плохо слышу» |
| У | с нарушениями умственного развития | «Нужна простая и понятная информация» |

| Статус | Смысл | Ранг |
|---|---|---|
| `DP` — ДП | доступно полностью, без посторонней помощи | 3 |
| `DCH` — ДЧ | доступно частично, с оговорками | 2 |
| `DU` — ДУ | доступно с помощником (сопровождающим) | 1 |
| `VND` — ВНД | недоступно | 0 |

Фильтр «доступно для…» показывает маршруты с рангом ≥ 2, а с отметкой «со мной будет помощник» — с рангом ≥ 1. К каждому статусу есть пояснение: что именно мешает или помогает.

## Правила посещения

Уровень (`level`) правила и маршрута:

- `0` — свободное посещение, действуют общие правила и рекомендации;
- `1` — нужен билет или регистрация;
- `2` — нужно разрешение или пропуск, оформляемый заранее (заповедники, погранзона).

У правила есть: `title`, `short` (суть одним абзацем), `when` (когда касается), `steps` (что сделать), `basis` (закон или документ), `links` (официальные ссылки). Тесты проверяют, что у каждого правила есть основание, шаги и хотя бы одна ссылка на первоисточник, а каждое правило, упомянутое в маршрутах, есть в базе.

Правила и формулировки меняются: на каждой странице маршрута указана дата сверки и ссылки, по которым пользователь может проверить актуальные требования. Срочные изменения (закрытие тропы, новый порядок посещения) администратор публикует как объявление — оно сразу появляется вверху сайта.

## Треки и профили высот

Треки схематичные — для понимания, где проходит маршрут, а не для навигации. Конвейер в `tools/tracks/`:

1. `build-tracks.mjs` — для каждого маршрута берёт отношение OpenStreetMap (`route=hiking`) или строит пешеходный маршрут через опорные точки (OSRM, профиль foot, данные OSM); высоты — Open-Meteo Elevation API (Copernicus DEM GLO-90). Результат — `tracks.json`.
2. `fix-summits.mjs` — продлевает выбранные треки до настоящей вершины и пересчитывает профиль высот.
3. `to-js.mjs` (`npm run build:tracks`) — сохраняет результат компактным модулем `public/js/data/tracks.js`.

Тест проверяет, что каждый трек начинается не дальше 3 км от точки старта маршрута.

## Снаряжение

Каждая вещь в `gear.js` содержит категорию, название, вес и **объяснение, зачем она нужна**. Поле `if` — декларативные условия попадания в список: сезон, число дней, тип ночёвки, тип местности, особенности участников (`K, O, S, G, U, kids, elderly, dog`), сложность, клещевой регион, нужны ли разрешения, удалённость. Подбор — функция `buildGear` в `logic.js`; количество может умножаться на число дней (`perDay`) или считаться на группу (`group`).

## Как добавить или изменить маршрут

- **Через сайт.** Войдите администратором → «Администрирование» → «Маршруты» → «Новый маршрут». Форма проверяет те же правила, что и тесты. Изменение сразу видно в каталоге и попадает в журнал действий.
- **В коде.** Добавьте объект в `public/js/data/routes.js` и обложку `public/img/routes/<cover>-640.webp` и `-1280.webp`, при необходимости — трек (`tools/tracks`). Запустите `npm test && npm run check`. Новая база заполнится при первом запуске; в уже работающую базу маршрут проще добавить через администрирование.
